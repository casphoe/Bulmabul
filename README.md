# Bulmabul Online Board Game

Unity와 Firebase, Photon Fusion을 기반으로 제작 중인 부루마불 형식의 온라인 멀티플레이 보드게임 프로젝트입니다.  
로그인, 회원가입, 로비, 방 생성, 친구 시스템, 채팅, 주사위 뽑기, 주사위 인벤토리, 출석 보상, 방 초대, 게임 진행, 땅 구매, 건물 건설, 통행료 지급, 감옥, 여행, 찬스 카드, 게임 이탈 패널티, 승패 처리 기능을 구현했습니다.

단순한 보드 이동 게임이 아니라,  
온라인 유저 관리, 실시간 방 리스트, 친구/채팅, 턴 기반 게임 진행, 네트워크 동기화, 카드 시스템, 감옥/여행 규칙, 게임 종료 처리까지 포함한 구조로 개발하고 있습니다.

---

## 프로젝트 개요

본 프로젝트는 부루마불 형식의 보드게임을 Unity 기반으로 구현한 온라인 멀티플레이 게임입니다.

유저는 Firebase를 통해 로그인 또는 회원가입을 진행하고, 로비에서 방을 생성하거나 참여할 수 있습니다.  
방 생성 시 개인전 또는 팀전을 선택할 수 있으며, 맵 선택도 가능합니다.  
방 안에서는 준비하기, 방 나가기, 리더 넘기기, 친구 초대, 전체 채팅, 파티 채팅 기능을 사용할 수 있습니다.

게임 씬에서는 선택한 맵을 기준으로 보드가 생성되고, 플레이어 Pawn이 생성됩니다.  
자신의 차례가 되면 홀/짝을 선택한 뒤 주사위 게이지를 통해 주사위를 굴립니다.  
주사위 결과에 따라 Pawn이 이동하며, 도착한 칸의 타입에 따라 땅 구매, 건물 건설, 통행료 지급, 감옥, 여행, 찬스 카드 등의 기능이 실행됩니다.

## 주요 구조

프로젝트는 기능별로 스크립트 폴더를 분리하여 관리했습니다.

- `301.Account`
  - 계정 데이터, 출석, 재화, 전적, 이탈 패널티, 암호화 처리

- `302.Dice`

  - Firebase 로그인, 회원가입, 닉네임 중복 처리, 친구 데이터 처리

- `304.Photon`
  - Photon Fusion 기반 로비, 방 생성, 방 참가, 방 리스트, 네트워크 Runner 관리

- `306.Language`
  - 한국어 / 영어 언어 전환 및 로컬라이징 텍스트 처리

- `307.Rules`
  - 시작 재화, 시작칸 보너스, 승리 조건 등 게임 룰 데이터 관리

- `308.Room`
  - 방 멤버 상태, 팀 정보, 방 채팅 상태, 친구 초대 데이터 처리

- `309.Chatting`
  - 전체 채팅, 파티 채팅, 채팅 메시지 UI, 비속어 필터

  - 친구 목록, 친구 요청, 친구 채팅, 친구 프로필, 접속 상태 처리

- `311.Game`

  - 땅 깃발, 건물, 지붕 머티리얼 표시 처리

  - 감옥 탈출 선택 UI

- `316.TestGame`
  - 테스트 전용 강제 이동 키 기능

- `317.Travel`
  - 여행 비용 선택 UI, 여행 목적지 선택 UI, 여행 지역 검색, 목적지 정렬, 검색 결과 패널 전환, 목적지 소유자 표시

### 34. 여행 기능

- 부루마불 세계여행 기능 구현

- 플레이어가 여행하기를 선택하면 재화를 지불하고 여행 목적지 선택 상태로 전환
- 여행 비용을 지불하면 다음 자기 턴에 여행 목적지 선택 팝업 표시
- 여행 목적지 선택 후 선택한 지역으로 Pawn 이동
- 기존 순간이동 방식이 아니라 주사위 이동과 동일하게 보드 경로를 따라 이동하도록 수정
- 여행 이동 중 시작 지점을 지나면 한 바퀴를 돈 것으로 판단하여 시작칸 보너스 지급
- 한 바퀴 이후 새로 구매한 땅에서도 큰집 건설 조건이 정상 적용되도록 수정
- 장거리 여행 이동 시 Pawn 이동 속도를 보정하여 이동 시간이 과도하게 길어지지 않도록 처리
- 여행 이동 완료 후 도착한 칸의 이벤트 처리 가능
- 여행 카드 사용 시 여행 칸으로 먼저 이동한 뒤 다음 자기 턴에 목적지 선택 가능
- 여행 카드 사용 시 여행 비용 팝업이 표시되지 않도록 처리
- 여행 카드 사용 시 바로 목적지를 고르지 않고 먼저 여행 칸으로 이동하도록 처리
- 여행 카드 이동도 순간 이동이 아니라 보드 경로를 따라 한 칸씩 이동하도록 수정
- - 테스트 이동으로 여행 칸에 도착한 경우에도 일반 여행 흐름과 동일하게 처리 가능


### 35. 여행 목적지 선택 UI 기능

- 여행 목적지 선택 팝업에 전체 보드 지역 목록 표시
- GPM InfiniteScroll을 사용하여 여행 목적지 목록 구성
- 검색창에 아무것도 입력하지 않으면 전체 여행 지역 표시
- 검색어를 입력하면 해당 글자로 시작하는 지역만 표시
- 영어는 대소문자 구분 없이 검색 가능
- 한글 초성 검색 지원

  - 예: `ㄱ` 입력 시 `강릉`, `광주` 등 표시 가능
  - 예: `속` 입력 시 `속초` 표시 가능
  - 예: `a` 입력 시 `Area`, `Argentina` 등 표시 가능
- 검색 결과가 있을 경우 목적지 목록 패널 표시
- 검색 결과가 없을 경우 결과 없음 안내 패널 표시
- 검색 결과 있음 / 없음 상태에 따라 `TravelFound`, `NoTravelFound` 패널 자동 전환
- 목적지 목록 정순 / 역순 정렬 기능 구현

  - 정순: 0번 칸부터 마지막 칸까지 표시
  - 역순: 마지막 칸부터 0번 칸까지 표시
- 정렬 버튼을 누르면 현재 검색어를 유지한 상태로 목적지 목록 재갱신
- 검색 결과가 없는 상태에서 다시 결과가 있는 검색으로 변경하거나 정렬 버튼을 눌렀을 때 목록이 사라지던 문제 수정
- InfiniteScroll 갱신 전에 검색 결과 데이터를 먼저 수집하고, 패널 활성화 후 데이터를 삽입하도록 처리 순서 개선
- 목적지 아이템에 땅 소유자 정보 표시

  - 미소유 땅은 소유자 없음으로 표시
  - 소유된 땅은 해당 플레이어 이름 표시
- 팀전일 경우 팀 소유 정보를 별도 UI로 표시

  - 레드팀 소유
  - 블루팀 소유
- 개인전일 경우 팀 정보 UI가 표시되지 않도록 처리
- 여행 카드 사용으로 목적지 선택권을 얻은 경우에도 같은 목적지 선택 UI를 사용하도록 구성

### 37. 찬스 카드 타입

현재 코드 기준 찬스 카드 타입은 다음과 같이 구성되어 있습니다.

- `ReceiveMoney`
  - 은행에서 돈 받기

- `PayMoney`
  - 은행에 돈 내기
  - 천사 카드를 보유한 경우 세금 방어 선택 가능

- `MoveToStart`
  - 시작지점으로 이동

- `MoveToJail`
  - 감옥으로 이동

- `MoveForward`
  - 앞으로 N칸 이동

- `MoveBackward`
  - 뒤로 N칸 이동

- `PayToAllPlayers`
  - 모든 플레이어에게 돈 지급

- `ReceiveFromAllPlayers`
  - 모든 플레이어에게 돈 받기

- `MoveToNearestEnemyLand`
  - 현재 위치 기준 앞으로 가장 가까운 적 소유 땅으로 이동

- `AngelCard`
  - 통행료 또는 벌금 방어용 보관 카드
  - 상대 땅 통행료 방어 가능
  - 세금 칸 또는 세금 납부형 찬스 카드 방어 가능

- `JailEscapeCard`
  - 감옥 탈출용 보관 카드
  - 감옥 상태에서 사용 가능
  - 사용 후 감옥 상태 해제 및 카드 소비 처리

- `MoveToTravelCard`
  - 여행 칸으로 이동하는 보관 카드
  - 사용 시 여행 칸으로 먼저 이동
  - 다음 자기 턴에 여행 목적지 선택 가능

- 시작칸 도착 시 보유한 땅에 건물을 건설할 수 있는 구조 구현
- 내가 소유한 땅 중 건설 가능한 지역 선택 가능
- 선택한 지역에 작은집 / 집 / 큰집 / 호텔 건설 가능
- 시작칸 보너스 건설은 PendingActionType의 `BuildFromStart` 상태로 관리
- 여행 이동 또는 카드 이동 중 시작 지점을 통과해도 시작 보상이 지급되도록 처리
- 시작 지점 통과 이후 큰집 건설 조건이 정상 적용되도록 수정

### 40. 테스트 전용 이동 키 기능

- 개발 테스트를 위한 강제 이동 기능 구현
- 현재 코드 기준 `F1~F7`이 아니라 키보드 상단 숫자키 `1~7`을 사용
- `BulmabulDebugMoveTester.cs`에서 처리
- 테스트 이동은 내 턴일 때만 가능
- 게임 종료 상태에서는 사용 불가
- 일시정지 상태에서는 사용 불가
- 턴 처리 중에는 사용 불가
- 선택 대기 상태에서는 사용 불가
- 감옥 상태에서는 사용 불가
- 여행 목적지 선택 대기 중에는 사용 불가
- 이동 후 도착 칸 이벤트를 처리하도록 구성
- 숫자키 7번을 누르면 천사 카드, 감옥 탈출 카드, 여행 카드를 각각 1장씩 지급
- 테스트 카드 지급 후 카드 인벤토리 UI가 갱신되도록 Revision 값 갱신
- 보관 카드 기능, 카드 사용 조건, 카드 소비, UI 갱신 흐름을 빠르게 검증할 수 있도록 구성

### 테스트 이동 키

| Key | 기능 |
| --- | --- |
| 숫자키 1 | 가장 가까운 적 소유 땅으로 이동 |
| 숫자키 2 | 팀전일 때 가장 가까운 내 팀원 소유 땅으로 이동 |
| 숫자키 3 | 가장 가까운 찬스칸으로 이동 |
| 숫자키 4 | 시작 지점으로 이동 |
| 숫자키 5 | 가장 가까운 감옥칸으로 이동 |
| 숫자키 6 | 가장 가까운 여행칸으로 이동 |
| 숫자키 7 | 천사 카드, 감옥 탈출 카드, 여행 카드 각각 1장 지급 |

### 테스트 이동 상세 설명

- 숫자키 1은 통행료 지급, 땅 인수, 천사 카드 사용 여부를 테스트하기 위해 가장 가까운 적 소유 땅으로 이동합니다.
- 숫자키 2는 팀전에서만 사용하며, 가장 가까운 같은 팀 플레이어 소유 땅으로 이동합니다.
- 숫자키 3은 찬스 카드 기능을 테스트하기 위해 가장 가까운 찬스칸으로 이동합니다.
- 숫자키 4는 시작칸 보너스 지급 및 시작칸 건물 건설 기능을 테스트하기 위해 시작 지점으로 이동합니다.
- 숫자키 5는 감옥 기능을 테스트하기 위해 가장 가까운 감옥칸으로 이동합니다.
- 숫자키 6은 여행 기능을 테스트하기 위해 가장 가까운 여행칸으로 이동합니다.
- 개인전에서 적 소유 땅은 나를 제외한 다른 생존 플레이어가 소유한 땅입니다.
- 팀전에서 적 소유 땅은 같은 팀이 아닌 상대 팀이 소유한 땅입니다.
- 팀전에서 팀원 소유 땅은 나를 제외한 같은 팀 플레이어가 소유한 땅입니다.
- 숫자키 7로 지급된 카드는 카드 인벤토리에 표시되며, 카드 보유 여부에 따라 천사 카드 팝업, 감옥 탈출 카드 버튼, 여행 카드 사용 흐름을 테스트할 수 있습니다.

### 41. 파산 처리 시스템

- 기존에는 재화가 0 이하가 되면 즉시 패배 처리되는 방식이었습니다.
- 현재는 파산 횟수를 기준으로 1회 파산은 유예 상태, 2회 파산은 최종 패배로 처리하도록 구조를 개선했습니다.
- 세금, 통행료, 카드 비용 등으로 재화가 0 이하가 되었을 때 파산 횟수 증가
- 1회 파산 시 즉시 패배하지 않고 게임 계속 진행
- 1회 파산 상태에서는 bankrupt = false 상태 유지
- 시작 지점 통과 보상, 보너스 카드, 통행료 수익 등으로 재화를 얻으면 파산 위기 상태에서 회복
- 단, 파산 횟수는 유지
- 다시 재화가 0 이하가 되어 2회 파산이 발생하면 최종 패배 처리
- 2회 파산 시 bankrupt = true로 전환
- 2회 파산 시 보관 카드 제거, 감옥 상태 해제, 여행 상태 해제, 소유 땅 해제 처리
- 남은 플레이어가 1명일 경우 즉시 승리 처리로 연결
- 팀전에서는 상대 팀 전원이 파산 또는 탈락했는지 확인하여 승리 조건 처리 가능

## 게임 승리 조건 설계

`BulmabulRule` 기준으로 승리 조건은 다음과 같이 확장 가능하도록 구성했습니다.

### 승리 조건 타입

- `BankruptcyLastSurvivor`
  - 다른 플레이어들이 모두 파산하고 마지막까지 남은 플레이어가 승리

- `LandmarkMonopoly`
  - 관광지 또는 랜드마크 독점 시 승리

- `LineMonopoly`
  - 특정 라인 또는 구역을 통일하면 승리

- `TurnLimitScore`
  - 제한 턴 종료 후 보유 재화와 자산 점수로 승리 판정

- `None`
  - 승리 조건 미사용 또는 테스트 상태

### 개인전 승리 조건

- 다른 플레이어가 모두 파산하거나 탈락하면 마지막 생존자가 승리
- 제한 턴 사용 시 보유 재화와 땅 가치, 건물 가치를 기준으로 점수 계산 가능
- 랜드마크 독점 또는 라인 독점 승리 조건 적용 가능

### 팀전 승리 조건

- 상대 팀 플레이어가 모두 파산하거나 탈락하면 남은 팀이 승리
- 팀 전체 자산을 합산하여 점수 판정 가능
- 팀 기준 라인 독점 또는 랜드마크 독점 조건 적용 가능

## 추후 수정 예정 오류

### 1. 프로필 이미지 403 오류

현재 프로필 이미지 로드 중 403 오류가 발생하여  
이미지가 정상적으로 불러와지지 않는 현상이 있습니다.

게임 플레이에 직접적인 영향을 주는 큰 오류는 아니기 때문에  
게임 승리 및 패배 기능 구현 완료 후 수정할 예정입니다.

### 확인 예정 사항

- Firebase Storage 접근 권한 확인
- 프로필 이미지 다운로드 URL 만료 여부 확인
- Firebase Storage Rules 설정 확인
- 프로필 이미지 업로드 후 URL 갱신 여부 확인
- 기존 이미지 삭제 후 새 이미지 저장 방식 확인
- 비회원 / 회원 상태에 따른 프로필 이미지 접근 권한 확인
- 친구 목록에서 프로필 이미지 URL이 오래된 URL로 남아있는지 확인

## 현재 프로젝트 진행 상태

현재 프로젝트는 온라인 멀티플레이 보드게임에 필요한 핵심 시스템 대부분을 구현한 상태입니다.

로그인, 회원가입, 로비, 방 생성, 방 검색, 방 정렬, 친구 시스템, 친구 채팅, 전체 채팅, 파티 채팅, 방 초대, 주사위 뽑기, 주사위 인벤토리, 출석 보상, 게임 맵 생성, 턴 진행, 주사위 게이지, Pawn 이동, 땅 구매, 건물 건설, 통행료 지급, 감옥, 여행, 찬스 카드, 게임 이탈 패널티, 승패 처리까지 구현되어 있습니다.

현재는 게임 완성도를 높이기 위해  
찬스 카드 시스템 고도화, 시작칸 건물 업그레이드, 테스트 이동 기능 정리, 게임 승리 조건 정리, 프로필 이미지 오류 수정을 진행 중입니다.

전체적으로 핵심 시스템 구현 단계는 대부분 완료되었으며,  
현재는 승리 조건 안정화, 시작칸 건설 흐름 개선, UI 편의 기능 보완 단계입니다.
